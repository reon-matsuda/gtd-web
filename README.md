# タスク管理 / GTD — 静的ホスト版

画面を GitHub Pages に置き、データは Google Apps Script の JSON API から取得する構成。

## ファイル

| ファイル | 役割 | 更新時 |
|---|---|---|
| `index.html` | アプリ本体 | 差し替える |
| `app.css` | Tailwind のビルド済みCSS | 差し替える |
| `sortable.min.js` | 並べ替え用ライブラリ | ほぼ変わらない |
| `config.js` | **接続先の設定** | **触らない（自分の設定が入っている）** |

更新のたびに置き換えるのは `index.html` と `app.css` の2つだけ。
`config.js` は最初に1回書けば、以降そのままで構わない。

## 初回の設定

1. `config.js` の `apiUrl` を、Apps Script のウェブアプリURL（末尾 `/exec`）に書き換える
2. 4ファイルをリポジトリの直下に置く
3. Settings → Pages → Branch `main` / `/ (root)` → Save

## 使い方

`https://ユーザー名.github.io/リポジトリ名/?key=各自のアクセスキー` を各人に渡す。
一度開けばキーは端末に保存されるので、次からは `?key=` なしのURLでも開ける。

## 設計上の決まりごと

- **アクセスキーが唯一の身元確認手段。** 静的ホストからの通信にはGoogleのログイン情報が
  乗らないため、サーバーからは全員が匿名に見える。キーは1人1本、漏れたら失効・再発行する。
- **`config.js` にキーを書かない。** このファイルはインターネットに公開される。
- **1回のPOSTは64KBまで。** Apps Script は応答前に別ドメインへ転送し、その際ブラウザが
  POSTをGETに書き換えて本文を捨てるため、大きい本文は黙って消える。
  `chunkOps()` がバイト数で分割している（文字数ではない。日本語は1文字3バイト）。
- **全リクエストにナンスを付ける。** 転送経路で別のリクエストの応答を掴む事故が実測されたため、
  番号が一致しない応答は破棄して再送する。

## リポジトリを Public にしてよい理由

置いてあるのは画面のコードだけで、タスクのデータもアクセスキーも含まれない。
データは Google のスプレッドシートにあり、キーは各自のブラウザにある。
